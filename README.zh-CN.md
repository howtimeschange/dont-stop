# Don't Stop

[English](README.md) | [简体中文](README.zh-CN.md)

一个面向 Codex 及兼容 Agent Skill 运行时的自主交付闭环技能：

> 实现 → 测试 → 修复 → 复验 → 自审 → 证据化交付

`dont-stop` 会让已经获得授权的开发任务持续穿过可恢复故障，直到请求的结果
真正得到验证。它解决的核心问题是：Agent 写完代码、跑一次检查，就把后续调试
或验收工作重新交还给用户。

## 它会强制执行什么

- 修改前先检查真实仓库、工作区、项目指令、规格文档、测试和运行状态。
- 把用户请求转换成可观察、可验证的验收标准。
- 实现满足验收标准的最小完整改动。
- 先运行定向检查，再根据风险扩大到回归、构建、打包、渲染、导出或真实界面验证。
- 测试或真实流程失败时定位根因、完成修复，并在可行时补充回归测试。
- 修复后重新运行受影响的检查，而不是只报告第一次失败。
- 交付前检查最终 Diff、运行结果、生成物、安全问题和任务边界。
- 只使用当前已经取得的验证证据进行交付。

这个技能认为单元测试通常是必要条件，但不一定是充分条件。涉及 UI、集成、
浏览器、第三方模型、导出文件、桌面安装包和正式发布时，应尽量验证最接近用户
实际使用的真实表面。

## 长任务与上下文压缩连续性

长任务可能跨越多个模型上下文窗口。对于多阶段或容易触发上下文压缩的任务，
`dont-stop` 会在昂贵操作前维护一份轻量 checkpoint。它优先使用宿主能够跨压缩
保存的一等计划状态，例如 `update_plan`。如果不能保证这种持久化，就使用
`.codex-tmp/dont-stop/<task-id>/checkpoint.json` 作为非交付物备用方案。

checkpoint 保存有边界的结构化状态，而不是完整对话记录：

- 当前步骤、已完成步骤、单一下一动作，以及证据指针或结果；
- 稳定的验收标准状态，以及带输入指纹和结果的已完成、失败或进行中动作记录；
- 任务范围、授权边界、适用时的请求 ID，以及防重复清单。

它不会保存大段日志、原始对话、密钥、Token 或截图。上下文压缩或任务交接后，
Agent 会先读取 checkpoint 和当前计划，只核对当前步骤，并保留已经验证的工作。
如果状态缺失或互相矛盾，只做一次有边界的盘点再继续；不能仅因为发生了上下文
压缩就从原始第一步重新开始。用户追加范围时，只追加或修订受影响的步骤，同时
保留已验证步骤及其证据。

## 动作状态门

在每次昂贵的读取、写入、测试或部署前，技能都会记录动作键：

```text
operation_key = phase | target | operation | input-hash
```

记录状态决定下一步动作：

| 状态 | 下一步动作 |
| --- | --- |
| `verified` | 复用已有证据；只有输入或依赖变化时才重新运行。 |
| `failed` | 改变假设或输入后才能重试。 |
| `unknown` | 先查日志、状态或资源回读，再决定是否重发。 |
| `in_progress` | 先确认原动作是否仍在执行。 |
| `blocked` | 完成安全的独立工作，然后报告阻塞点。 |

外部操作的超时、中断或响应丢失都归类为 `unknown`，不能直接视为失败。外部写入
必须先回读再重试，绝不盲目重发相同请求。如果同一个动作键连续两次拥有相同输入
和结果，禁止第三次原样执行；必须改变假设或输入、等待明确的状态变化，或带着已有
证据停止并报告阻塞点。

## 适用场景

适合以下实现类请求：

- 开发或补齐一个功能。
- 修复缺陷并验证回归结果。
- 接手并继续尚未完成的开发任务。
- 实现接口集成、业务工作流、脚本、UI 或数据交付物。
- 完成修改、自己测试、修复测试中发现的问题，然后再交付。

典型触发语句：

```text
先实现，实现完后自己测试，测试中发现问题自己修复，修复完成后再交付给我。
改完自己测试，有问题自己修复，确认没问题再交付。
不要停在分析，直接实现并跑通完整流程。
```

如果用户明确要求的只是探查、规划、Review、诊断、状态汇报或解释，并没有授权
修改，则不应使用这个技能执行变更。

## 安装

把仓库克隆到 Codex 的技能目录：

```bash
git clone https://github.com/howtimeschange/dont-stop.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/dont-stop"
```

重启 Codex 或新建一个任务，让技能目录重新加载。

更新已经安装的版本：

```bash
git -C "${CODEX_HOME:-$HOME/.codex}/skills/dont-stop" pull --ff-only
```

## 使用方法

显式调用：

```text
使用 $dont-stop 完成这个功能，所有适用检查通过以后再交付。
```

当实现类请求符合 `SKILL.md` 中的触发描述时，Codex 也可以隐式选择这个技能。

## 完整闭环

1. **确认交付契约**：检查当前真实状态，定义可观察的验收标准。
2. **完整实现**：遵循项目现有架构和约定，完成范围明确的改动。
3. **分层验证**：运行适用的静态检查、定向测试、回归测试、构建、渲染、导出、
   运行态验证和结果读回。
4. **自主修复**：定位失败根因，完成修复、补充覆盖，并重新运行受影响的检查。
5. **最终自审**：检查 Diff、实际行为、生成物、安全问题和无关文件边界。
6. **证据化交付**：说明结果、验证证据、剩余限制，以及用户要求的 Commit、
   产物或 Release 标识。

## 安全边界

“Don't Stop”代表穿过安全且可恢复的问题继续推进，不代表扩大用户授权范围。

这个技能不会自动授权：

- 发布生产环境或执行真实业务提交
- 破坏性数据库迁移或删除数据
- 支付或发送外部消息
- 用户没有要求的 Commit、Push、Release 或上传
- 绕过登录、双重验证、缺失凭据或需要用户决定的重大产品问题

遇到这些边界时，Agent 应先完成所有安全且独立的工作，然后明确说明需要用户
提供的唯一操作或决策。
